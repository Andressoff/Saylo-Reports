# Saylo — техническая концепция и паспорт проекта

**Версия проекта:** 1.0.0
**Редакция документа:** 2.0
**Статус:** активная разработка
**Платформа:** Windows 10
**Основной язык интерфейса:** русский
**Рабочий каталог:** `C:\Saylo`

---

## 1. О проекте

**Saylo (Сайло)** — самостоятельное интерактивное приложение для домашних занятий по развитию и коррекции речи детей.

Главная задача Saylo — организовать индивидуальный процесс речевого обучения: от знакомства со звуками до их использования в самостоятельной речи.

Программа должна не просто предлагать ребёнку набор упражнений, а постепенно формировать индивидуальную программу занятий на основании:
- профиля ребёнка;
- выбранных целевых звуков;
- текущего этапа обучения;
- результатов предыдущих занятий;
- повторяющихся трудностей;
- динамики речевого развития.

Родитель создаёт профиль ребёнка и при необходимости определяет целевые звуки. Дальнейшую организацию занятий должен выполнять Saylo Core.

Ребёнку предоставляется простой интерфейс с минимальным количеством действий. Основной сценарий — нажать кнопку «Начать занятие» и выполнять предлагаемые задания.

Saylo является вспомогательным домашним инструментом и не заменяет профессиональную диагностику и работу логопеда.

## 2. Основная концепция

Saylo строится вокруг трёх основных участников:

**Ребёнок**
- выполняет игровые речевые задания;
- слушает образцы звуков и слов;
- повторяет произнесённый материал;
- получает понятную и доброжелательную обратную связь;
- постепенно осваивает речевые навыки.

**Родитель**
- создаёт и ведёт профили детей;
- определяет целевые звуки;
- наблюдает за историей занятий;
- отслеживает динамику и трудности;
- управляет сохранёнными данными.

**Saylo Core**
- получает информацию о профиле;
- определяет доступные учебные задачи;
- выбирает подходящий этап обучения;
- формирует план занятия;
- контролирует последовательность заданий;
- принимает и сохраняет результаты;
- анализирует повторяющиеся трудности;
- адаптирует дальнейшее обучение.

Главный принцип: **родитель задаёт направление обучения, а Saylo самостоятельно организует процесс в пределах подтверждённых возможностей системы.**

## 4. Основные принципы разработки

### 4.1. Ребёнок в центре внимания

Интерфейс должен быть понятным, доброжелательным и не перегруженным информацией.

### 4.2. Без наказаний

Ошибки не должны сопровождаться негативными оценками, порицанием или наказаниями.

### 4.3. Индивидуальное обучение

Программа должна учитывать особенности конкретного профиля и историю предыдущих занятий.

### 4.4. Автономность Saylo Core

Ядро должно самостоятельно управлять логикой занятий. Родитель не должен вручную выбирать каждое следующее упражнение.

### 4.5. Обучение на накопленных результатах

Выводы о повторяющихся трудностях должны основываться на серии наблюдений, а не на одной попытке.

### 4.6. Разделение функций

Распознавание речи, акустический анализ, оценка правильности произношения и педагогическое решение являются разными задачами.

### 4.7. Безопасность

Голосовые данные и информация о ребёнке должны обрабатываться локально, если отдельным решением не предусмотрено иное.

### 4.8. Модульность

Каждый компонент должен иметь чёткую область ответственности и возможность независимого развития.

## 5. Архитектура приложения

Saylo разделяется на следующие основные подсистемы.

### 5.1. Electron Application

Отвечает за:
- запуск приложения;
- создание окон;
- системные возможности;
- взаимодействие между интерфейсом и основным процессом;
- IPC-коммуникацию.

### 5.2. Renderer / UI

Пользовательская часть приложения.

Содержит:
- детский интерфейс;
- родительский раздел;
- управление профилями;
- выбор целевых звуков;
- отображение занятий;
- результаты и прогресс;
- управление записями.

### 5.3. Saylo Core

Центральное управляющее ядро.

Основные обязанности:
- управление жизненным циклом занятия;
- получение учебного контекста;
- взаимодействие с профилями;
- формирование учебного плана;
- управление упражнениями;
- обработка результатов;
- оценка прогресса;
- определение дальнейших учебных задач.

Saylo Core не должен зависеть от конкретного интерфейса или конкретного механизма распознавания речи.

### 5.4. Profile System

Система индивидуальных профилей детей.

Отвечает за:
- создание профиля;
- хранение имени и заметок;
- настройки занятий;
- назначение целевых звуков;
- хранение текущих этапов обучения;
- управление статусом целевых звуков.

Профили являются самостоятельными объектами. История занятий хранится отдельно и связывается с профилем через `profileId`.

### 5.5. Phonetics System

Фонетическая подсистема.

Отвечает за:
- справочник звуков;
- классификацию фонем;
- связь звуков с учебным материалом;
- предоставление фонетических данных;
- подготовку материала для упражнений.

Фонетический справочник не является сам по себе анализатором правильности произношения.

### 5.6. Exercise System

Система упражнений.

Отвечает за:
- хранение каталога упражнений;
- подбор упражнений под целевой звук;
- привязку заданий к этапам обучения;
- передачу заданий контроллеру занятия;
- учёт сложности и последовательности выполнения.

Каталог упражнений должен развиваться отдельно от управляющего ядра.

### 5.7. Session Controller

Контроллер занятий.

Отвечает за:
- запуск занятия;
- получение выбранного профиля и целевого звука;
- управление текущим сценарием;
- выдачу упражнений;
- приём результатов попыток;
- регистрацию завершения этапов;
- завершение занятия.

### 5.8. Progress System

Система истории и прогресса.

Отвечает за:
- сохранение занятий;
- сохранение попыток;
- регистрацию результатов;
- учёт выполненных заданий;
- анализ динамики;
- подготовку отчётов;
- выявление повторяющихся трудностей.

### 5.9. Audio System

Аудиоподсистема.

Предназначена для:
- доступа к микрофону;
- записи голоса;
- воспроизведения записей;
- подготовки аудиоданных;
- сохранения аудиофайлов;
- передачи материала другим подсистемам.

### 5.10. Speech Recognition

Модуль распознавания речи.

Предполагается использование Faster-Whisper или другого локального движка.

Его задача — преобразование речевого сигнала в текст и получение вспомогательной информации о произнесённом материале.

Результат распознавания не является доказательством правильного произношения конкретной фонемы.

### 5.11. Pronunciation Analysis

Отдельная подсистема анализа произношения.

Её будущие задачи:
- анализ акустических характеристик;
- исследование признаков целевых фонем;
- сравнение акустических признаков с эталонными моделями;
- оценка качества и уверенности анализа;
- выявление возможных замен, пропусков и искажений звуков.

Текущий акустический анализатор извлекает характеристики аудиосигнала, но ещё не выполняет полноценное распознавание фонем и подтверждение правильности артикуляции.

### 5.12. Voice System

Подсистема голосового сопровождения.

Предназначена для:
- озвучивания инструкций;
- воспроизведения образцов;
- голосового сопровождения занятий;
- предоставления ребёнку понятной обратной связи.

Piper TTS рассматривается как лёгкий вариант локального синтеза речи. Подключение и окончательная конфигурация голосового движка развиваются отдельно.

### 5.13. Storage System

Система хранения данных.

Отвечает за:
- профили;
- настройки;
- историю занятий;
- результаты попыток;
- аудиозаписи;
- учебные данные.

Формат хранения определяется отдельно для каждой категории данных. Нельзя считать, что весь проект уже переведён на SQLite.

### 5.14. Adapters

Адаптеры для будущего взаимодействия с внешними системами.

Первоначально основная логика Saylo не зависит от OSA.

Интеграция с OSA должна осуществляться через отдельный интерфейс обмена данными.

## 6. Логика обучения

Saylo должен использовать последовательную систему логопедических этапов.

Основная последовательность:

1. `sound_awareness` — слуховое восприятие и распознавание целевого звука.
2. `sound_elicitation` — постановка и формирование звука.
3. `syllables` — закрепление звука в слогах.
4. `words` — закрепление звука в словах.
5. `phrases` — использование звука во фразах.
6. `sentences` — использование звука в предложениях.
7. `spontaneous_speech` — использование звука в самостоятельной речи.

Дополнительно предусматривается направление:

` sound_differentiation ` — различение звуков, которые ребёнок смешивает.

Это направление может использоваться отдельно или параллельно с основной последовательностью, когда это педагогически обосновано.

### Правила перехода между этапами

- Нельзя автоматически считать этап освоенным после одной успешной попытки.
- Результаты должны накапливаться.
- Необходимо учитывать повторяемость успешных и неуспешных выполнений.
- Нельзя путать правильный выбор ответа с правильным произношением.
- Подтверждение постановки звука и переход к этапам, требующим профессиональной оценки, должны предусматривать участие специалиста.
- Система должна различать подтверждённые результаты, предварительные наблюдения и недостаточно достоверные данные.

## 7. Персонализация обучения

Saylo должен постепенно переходить от фиксированных сценариев к персонализированному обучению.

Для каждого профиля система учитывает:

- имя ребёнка;
- заметки родителя;
- целевые звуки;
- приоритет звуков;
- активность учебных направлений;
- текущий этап;
- историю занятий;
- результаты попыток;
- подтверждённые этапы;
- уровень сложности.

### Принцип работы

1. Родитель создаёт профиль.
2. Родитель добавляет целевые звуки.
3. Saylo получает учебный контекст.
4. Core определяет доступные задачи.
5. Система формирует план занятия.
6. Ребёнок выполняет задания.
7. Результаты сохраняются.
8. Анализатор оценивает накопленные данные.
9. Core использует полученные сведения при планировании последующих занятий.

**Важное ограничение:** адаптивное планирование не должно самостоятельно превращать предположительные результаты акустического анализа в подтверждённый логопедический диагноз или факт постановки звука.

## 8. Профили детей

Каждый ребёнок имеет отдельный профиль.

Предусмотренные поля:

- `id`;
- `displayName`;
- `createdAt`;
- `updatedAt`;
- `notes`;
- `targetSounds`;
- `preferences`.

Для целевого звука предусматриваются:

- `soundId`;
- `active`;
- `priority`;
- `notes`;
- `currentStageId`;
- `completedStages`;
- `confirmedStages`;
- `difficultyLevel`;
- `status`;
- даты создания и изменения.

Родительский раздел должен обеспечивать:
- создание профиля;
- просмотр сохранённых профилей;
- выбор активного профиля;
- редактирование данных;
- управление целевыми звуками;
- удаление или архивирование профиля;
- просмотр истории занятий.

При удалении профиля нельзя без отдельного решения удалять связанную историю занятий. Исторические результаты должны оставаться доступными или архивироваться вместе с необходимыми сведениями о профиле.

## 9. Принципы оценки речи

Saylo должен использовать несколько независимых источников информации.

### 9.1. Распознавание речи

Определяет, какое слово или фраза предположительно были произнесены.

### 9.2. Акустический анализ

Извлекает измеримые характеристики звукового сигнала.

### 9.3. Фонетический анализ

В перспективе должен определять признаки конкретных фонем и возможные варианты их реализации.

### 9.4. Педагогическая оценка

Определяет, можно ли считать учебную задачу выполненной и допустим ли переход к следующему этапу.

Эти результаты не должны смешиваться.

Система должна учитывать:
- качество записи;
- шум и посторонние звуки;
- недостаточную громкость;
- неоднозначность распознавания;
- единичные ошибки;
- повторяющиеся трудности;
- недостаточность данных.

Saylo не должен выдавать категоричные заключения, если имеющихся данных недостаточно.

## 10. Игровая система

Игровые механики предназначены для поддержания интереса ребёнка.

Предусматриваются:
- звёзды;
- достижения;
- визуальные поощрения;
- дружелюбный персонаж;
- понятные инструкции;
- небольшие игровые задания.

Поощрения должны отражать участие и старание ребёнка, а не создавать давление из-за неправильного произношения.

## 14. Безопасность и конфиденциальность

- Микрофон используется только в рамках предусмотренных функций.
- Запись должна запускаться понятным действием пользователя.
- Голосовые данные не отправляются во внешние сервисы без отдельного решения и согласия родителя.
- Должна быть предусмотрена возможность удаления аудиозаписей.
- Родитель управляет профилями и связанными данными.
- История занятий не должна случайно удаляться при изменении профиля.
- Необходимо использовать `contextIsolation: true`.
- Необходимо использовать `nodeIntegration: false`.
- IPC должен предоставлять только необходимые операции.
- Валидация входящих данных должна выполняться на стороне основного процесса и ядра.
- Ошибки распознавания и анализа не должны превращаться в категоричные выводы о ребёнке.

## 15. Будущая интеграция с OSA

Saylo является самостоятельным приложением.

OSA не является обязательной частью архитектуры и не должен управлять внутренней логикой Saylo.

В перспективе допускается подключение через отдельный адаптер.

Возможные направления интеграции:
- обмен информацией о занятиях;
- получение родительских уведомлений;
- взаимодействие с семейной системой;
- передача разрешённых сводных данных.

Интеграция не должна нарушать автономность Saylo и конфиденциальность данных ребёнка.

## 17. Правила дальнейшей разработки

1. Не смешивать независимые подсистемы.
2. Не создавать дублирующие механизмы при наличии уже работающего модуля.
3. Перед изменением проверять существующую реализацию.
4. Не считать функцию готовой только потому, что для неё создан метод или интерфейс.
5. Не подменять фонетический анализ обычным распознаванием текста.
6. Не делать выводов о постановке звука по одной попытке.
7. Не удалять историю занятий вместе с профилем без отдельного обоснованного решения.
8. Не добавлять тяжёлые зависимости без необходимости.
9. Проверять изменения небольшими последовательными этапами.
10. Создавать резервные копии перед крупными или рискованными изменениями.
11. Документировать изменения архитектуры.
12. Сохранять автономность Saylo Core.
13. Не усложнять интерфейс ребёнка функциями, предназначенными для родителя или разработчика.

## 18. Главный принцип Saylo

Saylo — не просто программа для повторения звуков и не набор разрозненных логопедических упражнений.

Это персональная система домашних речевых занятий, в которой:

- родитель определяет направление обучения;
- Saylo Core организует учебный процесс;
- упражнения формируют последовательность развития навыков;
- аудиосистема обеспечивает взаимодействие с голосом ребёнка;
- аналитические модули собирают и оценивают данные;
- система прогресса сохраняет историю и помогает выбирать дальнейшее направление работы.

**Конечная цель — создать самостоятельного, последовательного и адаптивного помощника для домашних занятий по развитию речи ребёнка, который учитывает историю обучения, уважает индивидуальный темп и не подменяет профессиональную логопедическую оценку.**
